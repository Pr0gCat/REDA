# 持續電路生成優化

使用者於 2026-09-30 指定的持續流程：

1. **觀察產物**：生成實際電路，檢查布局／投影、路徑與元件明細，記錄方塊數、非空氣包圍盒體積、實測延遲與世界指紋。指出具體浪費或錯誤的位置及影響。
2. **定位原因**：追查布局、佈線、元件實現、候選選擇或成本模型。確認問題源頭與所有受影響的呼叫路徑，區分前端邏輯與物理生成成本。
3. **提出通解**：以幾何、拓撲或時序條件描述修正，不以案例名稱分支。不新增第二個 router，不調低驗收、不略過物理驗證，不修改獨立 baseline 來使實驗通過。
4. **對照實驗**：同一來源及 lowered netlist，比較前後產物；保留原候選。檢查真值表／狀態軌跡、適當回歸、三次量測的決定性，以及跨平台或時序條件。計時不參與決定性的候選選擇。
5. **通過則提交**：只提交有量測收益且驗證通過的通解與必要證據；每次提交對應一個原因。失敗實驗撤回，記錄拒絕原因並換下一個問題。提交後繼續觀察下一輪。

每輪報告至少包含：觀察與位置、根因、通解、前後數據、驗證／限制、實作來源與 git commit。面積、延遲或生成時間若有取捨，需明確呈現，不能只報改善項目。

此目標持續執行，除非使用者要求暫停或變更範圍。Minecraft 客戶端認證與 simulator 驗證需分別標示；不能把 simulator 通過當作已在遊戲驗證。
