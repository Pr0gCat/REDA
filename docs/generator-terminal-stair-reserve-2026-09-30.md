# 普通路由只在尾端保留階梯預算

基準 afbd685。觀察：普通路由以整條分支的階梯數（有上限）扣除每次紅石粉刷新預算，許多不含階梯的中段也提早插入中繼器。這會增加跨段延遲。路由本身已有階梯前的強制刷新與完整強度／連通性驗證，因此可將同一保守預留量保留在尾端，讓中段使用完整粉線預算。

實作新增 TerminalStairs，僅普通非 strict／seed 路由選用。strict／seed 的 LatestLegalCell 不變；TotalStairs 留作獨立歷史參考。共用彎折規劃器提供尾端預留入口，原有 plan_bent_path 仍以全段預留運作，compile_legacy 及其强度預估／發射保持原樣。原型先前的全域修改沒有採用。

規則只看實際路徑、階梯與末端強度，沒有案例或訊號名稱。階梯前的強制刷新、實際載流檢查、終端要求及所有實體 verifier 均保留，不把缺乏合法刷新位置的路徑當作可用。

## 對照結果

兩種前端 XOR 的相同實體產物均改善：

| 指標 | 原生成器 | 本輪 |
|---|---:|---:|
| 最差世界穩定 game ticks | 14 | 12 |
| 平均世界穩定 game ticks | 7.4375 | 6.375 |
| 燈毛刺轉換數 | 2 | 0 |
| 驅動端毛刺轉換數 | 2 | 1 |
| 驅動最晚跳變 game ticks | 10 | 8 |
| 驅動最長錯值脈衝 game ticks | 4 | 2 |
| 驅動錯值脈衝總寬度 game ticks | 6 | 2 |

XOR 單一輸入毛刺維持 0。MUX、majority 兩前端的全部時序／燈／驅動指標不變；and4 與七段顯示器兩前端的全部現行品質指標不變。原生 and4 世界指紋有變，但不把方塊數或體積用作改善標準。兩個七段 compile_legacy 控制產物的全部診斷資料與修改前一致。

固定歷史形狀與信號基準不變。另加入改善後 current checkpoint，要求後續候選保留 XOR 時序與毛刺收益；主品質與六個形狀都增加重複編譯的世界指紋一致性檢查。觀測仍為每 game tick 結束的邏輯高低，未聲稱量測 tick 內脈衝。

## 驗證範圍

主品質 1024 次轉換、額外形狀 288 次轉換，均有獨立最終真值與完整燈／實際驅動端品質門檻；五個毛刺／路徑見證、12 個 DFF 測試通過。路由單元測試 67 個通過，包括歷史策略、強度、合法刷新位置與新尾端預留例子（24 格、預留 4：歷史兩個刷新、尾端一個刷新且末端強度 6）。没有跑全庫作為全綠聲明。

Viewer 原生測試原有固定 10088 方塊斷言已過時，修改前後本輪七段都是 7976。改為直接與編譯器的世界核對每個序列化座標、方塊種類及中繼器延遲，且核對完整數量與唯一性；這是 API 幾何一致性，不是方塊數品質門檻。其餘來源結構與真值檢查保留。

WASM 工具最初嘗試在唯讀位置安裝 wasm-bindgen 而失敗；改用本機已驗證的 0.2.126 runner，直接以 Cargo 執行 Node 測試，frontend 2、placement 6 個均通過，與原生對應測試數一致。根 crate 的 wasm32 check 通過。生成器改動沒有涉及前端語法、DFF 結構或公共資料格式；未聲稱 Minecraft 客戶端驗證或最高安全時脈量測。

最終含重複生成檢查的五組根 crate 回歸全部通過，主品質所有指標與歷史控制逐欄等於修改前；viewer 原生 46 通過、1 原本忽略，Node frontend 2／placement 6 通過。Web release bundle 已用既有 wasm-bindgen 生成；因唯讀環境無法安裝可選 wasm-opt，使用 `wasm-pack build --mode no-install --no-opt --target web viewer`，Rust release 最佳化仍啟用，仅略過附加 wasm-opt，不改專案設定。根庫原有 packing.rs unused_mut 警告未在本輪處理；未宣稱全庫／clippy -D warnings 全綠。

本輪通過且採用普通路由尾端預留策略；持續優化目標仍保持進行中。
