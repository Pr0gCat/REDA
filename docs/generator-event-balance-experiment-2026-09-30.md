# 單一輸入事件驅動的延遲補償實驗

基準 35b7318。前一輪 support 集合不能判定敏感路徑，本輪原型改用真值及事件方向：最多六個主要輸入，拓撲求所有 NOR／Merge 的真值，枚舉所有單一輸入切換。若某閘輸出兩端真值相同，但其所有舊高輸入都會關閉、另有新高輸入開啟，且沒有持續為高的控制輸入，才檢查空窗。

路由估算仍為實際中繼器數 × 2。事件 propagation 對高路徑建立的時刻取最早上升、對全部高路徑消失取最晚下降，NOR 加 2 tick。靜態輸出不變的訊號不作中間毛刺傳播。若最後關閉先於最早開啟，只對已有中繼器的關閉端增加 delay，絕不延遲接替高電位的開啟端；枚舉要求取最大補償，限制 delay 不超過 4。這仍是測試世界原型，未整合正式 generator realization／provenance，模型仍不能代表完整事件模擬。

第一版僅 NOR，兩個七段產物都改動 0 端點，完整主品質通過但全部指标不變，撤回。第二版納入 Merge（以真正 junction 位置求輸入端），Yosys 有三個端點：g7.in[0] 增 2 redstone ticks、g28.in[0] 增 3、g17.in[0] 增 3。名稱只是計算結果，沒有在規則中使用。第三版相同規則、每端最多增 1 tick。

| 最差世界／燈 ticks | 64 | 74 | 65 |

| 最長驅動錯值脈衝 ticks | 24 | 26 | 24 |
| 驅動錯值脈衝總寬度 | 2552 | 2760 | 2622 |

完整補償消除 0 → 2 的 a 驅動毛刺、4 → 0 的 f 驅動毛刺；兩個候選的時序及總脈衝寬度仍退步，完整補償最長錯值脈衝也退步。不能因目標見證修好或毛刺次數較少就採用。每端增 1 仍有 0 → 2 的 a、d 毛刺。

其餘三個主要產物均未改動。候選完成全部 1024 次主要真值轉換，但在 Yosys 七段時序驗收停止，未執行候選額外矩陣／見證，也未完成正式世界驗證整合，不宣稱全面通過。所有原型已撤回，沒有放寬門檻。相鄰 JSON 保存完整原型、各驅動指標與目標見證前後軌跡。

這輪證明事件方向能定位並消除部分缺口，但只靠增加現有中繼器延遲有實際時序代價；下一個實驗方向應縮短接替高路徑的傳遞，而不是繼續延長關閉路徑，並保持所有輸出品質不退步。

還原後三組回歸全部通過（主品質 1、矩陣 1、內部見證 5），世界指紋與全部驅動端固定基準逐欄一致。此提交僅記錄實驗證據，不含生成器優化。
