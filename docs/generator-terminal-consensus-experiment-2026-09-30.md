# 終端共同項及既有軌重用實驗

基準 `6ec3b41`，有效生成器仍為 `0de792e`。處理 Yosys 4 → 0 中 f 驅動端被燈遮住的 2 game tick 單一輸入脈衝，沿用一般 lowered NOR／Merge product-cube 分析，不辨識案例名稱。

## 通解實驗

第一版僅對沒有內部消費者的公開 Merge2 補共同項，避免改動共享中間邏輯。第二版加上缺少的 consensus 候選必須唯一，避免依變數名稱任意挑第一項：此網表 f 有一個缺口，a 有三個。第三版保持唯一缺口條件，搜尋既有訊號的反相 cube，若是共同項的子集合，重用該軌並只對其餘字面值新增 NOR。

f 的共同項為 `!d0 & !d1 & !d3`。第三版重用 n9，其函數為 `d0 | d1`，新增 `nor(n9,d3)`，與直接新增三輸入 NOR 邏輯相同，但新增層及主要輸入列的布局影響不同。搜尋既有軌使用固定排序。此仍是 optimized lowering 原型，未完成來源 ownership／provenance API 的一致整合，不構成正式可提交實作。

## Yosys 七段顯示結果

| 規則 | 最慢世界／燈 ticks | 平均世界 ticks | 燈毛刺轉換數 | 燈單一輸入毛刺轉換數 |
|---|---:|---:|---:|---:|
| 已提交基準 | 64 | 48.05078125 | 141 | 17 |
| 私有終端公開輸出 | 70 | 54.1875 | 153 | 15 |
| 唯一缺口、直接 NOR | 68 | 52.91796875 | 151 | 16 |
| 唯一缺口、重用既有軌 | 64 | 51.23828125 | 140 | 15 |

重用既有軌版的驅動端指標：最慢最後變動 62 → 60 tick、毛刺轉換數 146 → 145、單一輸入毛刺 18 → 15、最長錯值脈衝 24 → 18 tick，但錯值脈衝總寬度 2552 → 3178 tick。它確實消除 4 → 0 的 f 驅動脈衝，該轉換 f 沒有任何驅動觀測跳變；仍因總脈衝時間與平均穩定時間退步而拒絕，沒有放寬任何基準。

其他三個主要產物數值不變。三版均完成主品質的最終真值，但在時序或驅動脈衝驗收失敗，cargo 未執行其後額外矩陣及見證；不能宣稱候選整套回歸通過。

## 脈衝退步定位

新增主品質測試的每案例診斷檔，在品質斷言前保存完整驅動及燈軌跡，避免失敗候選只剩總數。比較重用版與基準後，驅動錯值脈衝寬度依輸出分解如下：

| 輸出 | 基準總寬度 | 候選總寬度 |
|---|---:|---:|
| a | 504 | 650 |
| b | 526 | 326 |
| c | 160 | 150 |
| d | 462 | 648 |
| e | 172 | 284 |
| f | 404 | 424 |
| g | 324 | 696 |

最大新脈衝見證為 4 → 3 的 e：基準沒有驅動跳變，候選在 tick 32 開啟、tick 48 關閉，增加 16 tick 錯值區間。修補一個 f 靜態缺口同時改變其他路徑；只檢查目標脈衝、次數或最長單一脈衝仍不足以驗收。

所有 lowering 原型已撤回。保留診斷檔功能、量測摘要、原型及新增脈衝見證。診斷檔位於 target/driver_timing_<case>_<frontend>.json，相鄰實驗 JSON 保存本次候選證據。後續可檢查提早放在輸入列的單一消費者閘是否能移向其消費者，減少新項對主要布局的牽動；這只是下一個待驗證方向。

還原後主品質、額外形狀矩陣及四個觀察／毛刺見證全部通過，原有與驅動端固定基準的全部指紋、時序及毛刺數值一致。
