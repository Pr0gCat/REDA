# Wide OR lowering

A logical `Or(n)` with more than three inputs previously passed through lowering as if it were a single physical merge. Plain lowering retained the unsupported wide cell, while optimized lowering failed to find a default library entry. The unchanged physical compiler correctly rejected the raw wide cell.

The topology layer now classifies wide OR as requiring expansion. One bounded-fan-in NOR recipe handles both selected output polarities. Each intermediate group computes its positive OR through NOR and inversion; singleton groups pass forward unchanged. The final stage emits the selected rail. Existing lowering, polarity selection and provenance consumers use this recipe without new APIs. Existing two-/three-input merge recipes, reference circuit builders, simulator, physical verifier and raw-wide-cell rejection remain unchanged.

The original control reproduces the defect. The isolated candidate checks every lowering entry at arities 4, 5, 7 and 10, both selected rails, public names, name collisions, idempotence, dependent AND composition and source ownership. The permanent integration check passes. Existing topology, lowering and polarity suites pass 33, 19 and 9 tests respectively, with no skips. The original raw physical entry checks remain intact and pass in the independent control/candidate harness.

Actual default compilation passes for 4-, 5- and 7-input OR. Each case has three independently generated, exported and reloaded worlds. Four and five inputs use every ordered input transition with two retained phases per transition; seven inputs uses every one-bit transition and every complement transition. All lowered gate outputs and public lamps are observed. Independent Python replay validates 9 worlds and 13,824 retained phases, including every gate/public event. All input states are covered. Three complete records are equal after excluding repetition/artifact names; each arity has one identical emitted artifact SHA across three retained files. Wrong truth, a removed real event and a flipped public event are rejected for each arity. The original 2,000-tick settling cap remains unchanged.

The adjacent evidence directory preserves the initial protocol, all raw traces and nine artifacts, independent auditor, original failed control, failed setup builds, exact compiler/run arguments, tested source snapshot and manifests. The applied helper is formatted with rustfmt separately; the rest of the existing source file is not reformatted. Its final bytes and the formatted permanent integration check are retained separately from the original tested snapshot.

This completes the wide-OR lowering defect, not the complete ROM/Mux, arbitrary composition, sequential quality or eight-item objective. Physical arity 10 and a physically generated dependent-AND composition are not claimed. The earlier full-library failures remain unresolved. Other routing recovery experiments remain isolated and are not included in this change. No block count or volume is an acceptance metric.
