# Native module instances and parameter overrides

The frontend previously rejected module instances, and elaboration owned only the root scope. It now elaborates each module with independent parameter and signal maps, then links its checked RTL ports into the parent. Child inputs receive parent expressions; child outputs drive validated parent targets, including slices and concatenations. All widths must match exactly. The existing complete-signal resolver still checks every bit for undriven nets, multiple drivers and combinational loops. No physical generation, simulator, verifier or quality thresholds changed.

Supported syntax includes explicit named or positional port lists, nested modules across source files, multiple instances in one declaration, integer parameter overrides by name or position, and dependent/local defaults. Override expressions resolve in the parent; defaults resolve independently in each child, and localparams cannot be overridden. Instance names share the declaration namespace. Unknown/duplicate modules and ports, duplicate overrides, recursion, invalid writable targets and width/driver failures are source errors. Static hierarchy depth over 128 is Unsupported. Arrays, open/omitted/implicit/wildcard connections, inout, packed/sized parameters and broader constant operations remain incomplete. These refusals are not counted as implemented functionality.

Existing positive-edge feed-forward/enable DFFs work inside nested modules when each clock is directly connected through scalar input ports. At this checkpoint the single-clock restriction applied across all instances. The subsequent [independent-clock extension](native-multiclock-2026-10-02.md) removes that global restriction with physical state/event proof; reset, negedge and general FSM/counter support remain unfinished. No simulator-only initialization or extra dwell stages were added.

Repeated module syntax keeps distinct instance IDs and original source nodes. Child debug signal bindings preserve qualified names such as `low.core.q`, so `signal_bits()` and `gates_for_signal_bit()` do not confuse identical local declarations. The optional binding name has a serde default and is omitted on root/legacy sidecars; old root lookup/JSON behavior is retained. Tests round-trip hierarchical debug data and check nested/differently sized instance bindings.

## Independent proof and physical evidence

The four-input hierarchy fixture nests two independently elaborated two-bit XOR modules. Its exact netlist equals independently written flat XOR-5. All 512 retained setup/target phases check actual implemented signals and public outputs against the literal oracle. Separate source tests cover distinct overrides/defaults, all 16 input rows, cross-file concatenation connections, invalid driver/recursion scopes, a 256-step independent register-state oracle and exact full-seven-segment netlist equivalence.

Full native hierarchical seven segment records every implemented gate, public driver/lamp and landing event for all 512 phases. Three complete runs are byte-identical to each other and to the previously frozen qualified native default. Its existing improvement is preserved: worst44, target total8671, output glitch transitions83, output pulse ticks1385; setup total8636. This is hierarchy compatibility with the accepted optimization, not a newly improved generator.

The optional Yosys bridge initially failed because it left module-instance cells for a reader that accepts only gates. Its synthesis script now runs standard [Yosys flatten](https://yosyshq.readthedocs.io/projects/yosys/en/v0.50/cmd/flatten.html) after process lowering. Native and fresh Yosys four-input traces are each byte-identical to their earlier independent flat-parameter artifacts (worst12, target total1567, no output glitches/pulses). These simple Unified3d worlds are unsealed; their optimization audit correctly remains unaccepted.

Hierarchical Yosys seven segment is independently synthesized and differs from its flat source in gate ordering and physical quality: worst74, target total13975, output glitch transitions135, output pulse ticks3217. It is a truth/event-validated independent implementation, not a claimed nonregressing optimization relative to flat Yosys. A fresh flat Yosys run remains byte-identical to its unchanged frozen baseline. Native and Yosys hierarchical seven segment both pass the independent literal ten-digit table (10..15 dark), implemented/public event replay and landing checks. Each hierarchy probe has three identical complete runs.

Native/auto CLI generation of the full hierarchical seven segment succeeds with `REDA_PYTHON=/definitely/missing/python`. Native and actual Yosys hierarchical DFFs pass the existing litematic save/load, power-on, edge/hold/enable physical protocol; existing checks and dwell are unchanged.
