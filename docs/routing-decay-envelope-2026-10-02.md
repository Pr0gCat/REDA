# Preserve a failed branch's decay envelope

A fixed two-height route fixture isolates lost information at the typed planner boundary. The historical router refuses a branch from `(30,1,49)` to the approach `(28,20,30)` because its staircase cannot host enough refreshes. It records 22 above-plane branch cells for congestion charging. The typed router refuses the same branch, but its generic PhysicalInvariant refusal previously lost the path and returned zero charge cells to the planner. This can leave repeated negotiation attempts pricing none of the geometry responsible for a decay failure. It does not prove the cause of the still-failing arithmetic counters.

The responsible typed failure now represents SignalDecay with the exact branch path and sink. The planner converts that path into charge cells using its unchanged `y > PLANNER_Y` rule, and restores the existing labelled decay message. Optional sink identities on other Refused/InvalidRequest failures are also preserved instead of defaulting to the first consumer. Fragment repair identifies the explicit sink for the new failure. No strength calculation, simulator, physical verifier, search budget, or accepted-route rule changes.

The regression compares the complete original error string, corridor, charge vector and failed reservation against `legacy_lay_net_reference`. Before the fix, the charge assertion fails (22 versus 0). Afterwards every comparison passes. All 69 routing tests and all three original complete Route parity tests pass again. Arithmetic source/growth/clock initialization remains separate unfinished work; this isolated failure-envelope repair does not assert that a counter now routes or meets physical state/event requirements. No complete root rerun follows this repair, and all eight goal items remain incomplete.

Raw before/after and regression logs and hashes are retained alongside this note. The fixture is a routing refusal experiment; it is not Minecraft conformance or a new successful physical circuit qualification.
